# Clean Windows release check

This procedure is **pending**, not a record of a completed test. The development machine already has the x64 VC runtime. Windows Sandbox/VM facilities are unavailable here. Use a disposable Windows x64 VM with a snapshot and a fresh standard-user account; keep personal DAW projects out of the VM.

1. Copy the exact setup EXE, installer manifest and retained 1.2.1 ZIP into the VM. Verify SHA256 against the manifest. Record the Windows build, setup hash, account privilege and VM configuration. Do not disable Windows security warnings to conceal this preview's unsigned status.
2. On a fresh snapshot without a suitable x64 VC runtime, run setup as current user and capture `/LOG="C:\TestLogs\install.log"`. Check that the Microsoft-signed prerequisite requests elevation, installs successfully and lets setup finish. Confirm its signature and version. Restart if requested.
3. On a fresh snapshot, cancel prerequisite elevation. Setup must stop without installing EMBERFOX. Record the message and log. Do not remove or downgrade shared runtimes on a working machine to manufacture this case.
4. Test current-user setup with default destinations. Check the whole VST3 bundle, optional standalone, offline guide, AGPL notices and corresponding source. Add the VST3 path in a real DAW, rescan and load the plugin. Open standalone and select working audio devices. Confirm the editor, controls, presets, bypass, Help/About and resize limits. Play a quiet test signal first; audition all modes and monitor output levels.
5. Save a DAW project with non-default settings, close/reopen it and compare settings/audio. Automate Drive, Mix, Output, Mode and bypass. Test mono/stereo at supported rates/block sizes. Record the DAW/version, audio device, settings and any warnings.
6. Add a user-created text file beside the application and an unrelated file beside the plugin bundle. Reinstall/update using the same scope and paths. Confirm both files survive, the DAW project restores, no duplicate plugin appears and the runtime is skipped when already compatible. Separately seed the old 1.2.1 manual bundle/executable and test upgrading it.
7. Uninstall through Windows Installed Apps. Confirm owned product binaries, shortcuts and registration are removed; user files, unrelated plugins, DAW projects and shared Microsoft runtime remain. Rescan the host. Reinstall and verify recovery.
8. Repeat from a clean snapshot with all-users installation under administrator approval, custom paths containing spaces, plugin-only component selection and standard-user execution. Record default/custom destinations and check that uninstall respects each installation scope. Avoid simultaneous per-user/all-users copies during the primary update test.
9. For rollback, restore the complete retained 1.2.1 VST3 bundle while the host is closed and open a backup project. Record compatibility and remove the test installation afterward.
10. When a real certificate is supplied, repeat using the signed artifact. Verify setup, uninstaller, plugin and standalone with SignTool `/pa /all /v`; confirm timestamp and displayed publisher. Missing-identity rejection tests do not establish the positive signing path.

Record pass/fail evidence, screenshots and logs in a dated validation report tied to the installer SHA256. A release gate stays open until fresh-machine prerequisites, actual DAW audio and final signing behavior have been exercised. Record non-sensitive compatibility issues in the public repository; publisher contact details can be added when available.
